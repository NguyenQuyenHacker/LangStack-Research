# Test đồ thị LangGraph (`pytest`)

> Ba khuôn viết unit test cho đồ thị LangGraph có cấu trúc tùy biến: chạy cả luồng, chạy một node, chạy một đoạn giữa.
> Cơ chế checkpointer dùng xuyên suốt các test do file [checkpointers](../02-persistence/02-02-checkpointers.md) phụ trách; ở đây chỉ dùng lại, không giảng lại.

---

## 1. Tổng quan

Ta sẽ cùng nhau tìm hiểu  các khuôn test dành riêng cho đồ thị LangGraph có cấu trúc tự dựng (tự thêm node, edge). Nó khác trang test cho `create_agent` của LangChain — cái đó dành cho người mới, dùng agent dựng sẵn; còn ở đây ta test đồ thị mình tự vẽ.

Xuyên suốt cả trang: **đồ thị LangGraph phụ thuộc state**. Vì có state, nếu dùng lại một đồ thị đã compile hoặc một checkpointer cũ giữa các test, trạng thái của test trước rớt sang test sau. Cả ba khuôn dưới đây đều xoay quanh việc kiểm soát state cho sạch.

Điều kiện đầu: cài `pytest`.

```bash
pip install -U pytest        # -U để lấy bản mới nhất
```

Trang tài liệu dùng `assert` để kiểm kết quả, không `print`. Nên các khối "Kết quả" dưới đây ghi *giá trị được assert* (suy trực tiếp từ câu `assert` trong nguồn), không phải dòng stdout, và không có output nào phải dựng lại.

## 2. Khuôn nền — dựng đồ thị mới cho mỗi test

Vấn đề đầu tiên phải xử lý: state rò rỉ giữa các test. Khuôn giải quyết là dựng đồ thị *trước mỗi test*, rồi compile *bên trong test* với một checkpointer mới toanh.

**Vấn đề** Nếu compile đồ thị một lần rồi xài chung cho mọi test, checkpointer giữ lại state của lần chạy trước. Test A ghi vào `thread_id="1"`, test B cũng đọc `thread_id="1"` và thấy dữ liệu của A. Test lúc đó đậu hay rớt tùy thứ tự chạy — lỗi khó lần nhất.

**Cách làm.** Tách phần dựng đồ thị ra một hàm `create_graph()` trả về đồ thị *chưa compile* (`StateGraph`). Mỗi test gọi lại hàm này, tự tạo checkpointer riêng, rồi mới compile. Hai test không dùng chung state nào.

Đồ thị mẫu tuyến tính, đi qua `node1` rồi `node2`, mỗi node ghi vào một khóa state duy nhất `my_key`:

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver

def create_graph() -> StateGraph:                                       # trả về đồ thị CHƯA compile, gọi lại được nhiều lần
    class MyState(TypedDict):                                           # state chỉ có một khóa my_key
        my_key: str

    graph = StateGraph(MyState)
    graph.add_node("node1", lambda state: {"my_key": "hello from node1"})   # mỗi node ghi đè my_key bằng chuỗi của nó
    graph.add_node("node2", lambda state: {"my_key": "hello from node2"})
    graph.add_edge(START, "node1")                                      # luồng: START → node1 → node2 → END
    graph.add_edge("node1", "node2")
    graph.add_edge("node2", END)
    return graph

def test_basic_agent_execution() -> None:
    checkpointer = MemorySaver()                                        # checkpointer MỚI cho riêng test này
    graph = create_graph()                                             # đồ thị mới, chưa dính state cũ
    compiled_graph = graph.compile(checkpointer=checkpointer)          # compile tại đây, không tái dùng bản compile ngoài
    result = compiled_graph.invoke(
        {"my_key": "initial_value"},                                  # state đầu vào
        config={"configurable": {"thread_id": "1"}}                   # thread_id định danh một phiên state
    )
    assert result["my_key"] == "hello from node2"                      # chạy hết luồng → giá trị cuối là của node2
```

**Kết quả** (giá trị được assert, không phải stdout):

```
result == {"my_key": "hello from node2"}      ← node2 chạy sau cùng nên ghi đè my_key lần cuối
```

**!Note:** Cái phải mới *cho mỗi test* là cả `create_graph()` lẫn `checkpointer`, không chỉ một trong hai. Giữ lại checkpointer cũ mà chỉ tạo đồ thị mới thì state vẫn rò. Đây là lỗi im lặng: test chạy không báo lỗi, chỉ đậu/rớt tùy thứ tự.

## 3. Test riêng từng node — `graph.nodes`

Khi muốn kiểm logic của đúng một node mà không chạy cả luồng, lấy tham chiếu node đó qua `graph.nodes` rồi `invoke` thẳng.

**Vấn đề** Node2 có bug, nhưng để tới được node2 phải chạy qua node1 trước. Chạy cả luồng chỉ để test một node vừa chậm vừa lẫn: không rõ giá trị sai là do node1 hay node2.

**Cách làm.** Đồ thị đã compile phơi tham chiếu tới từng node qua `graph.nodes`, tra bằng tên. Gọi `.invoke()` trên một node là chạy đúng node đó với state ta đưa vào.

```python
# create_graph() như định nghĩa ở Mục 2

def test_individual_node_execution() -> None:
    checkpointer = MemorySaver()                                       # vẫn tạo, nhưng sẽ bị bỏ qua (xem !Note)
    graph = create_graph()
    compiled_graph = graph.compile(checkpointer=checkpointer)
    result = compiled_graph.nodes["node1"].invoke(                     # gọi thẳng node1, không đi qua node2
        {"my_key": "initial_value"},                                  # state đầu vào cho riêng node1
    )                                                                 # không cần config/thread_id
    assert result["my_key"] == "hello from node1"                     # nhận đúng đầu ra của node1
```

**Kết quả** (giá trị được assert):

```
result == {"my_key": "hello from node1"}      ← chỉ node1 chạy, node2 không được gọi
```

**!Note:** Gọi node qua `graph.nodes[...].invoke()` **bỏ qua mọi checkpointer** đã truyền lúc compile. Vì vậy ở đây không có `thread_id`, và cũng đừng trông đợi state được lưu lại hay các hiệu ứng của checkpointer. Trong ví dụ trên `checkpointer` vẫn được tạo nhưng không có tác dụng gì — nó chỉ ở đó cho khớp khuôn compile.

## 4. Test một đoạn giữa đồ thị — partial execution

Với đồ thị lớn, đôi khi ta chỉ muốn test một đoạn giữa (ví dụ node2→node3) mà không chạy node1 đầu luồng lẫn node4 cuối luồng.

**Vấn đề** Đoạn cần test nằm ở giữa. Chạy từ đầu thì phí công qua các node trước; mà bỏ chúng đi thì state đầu vào cho đoạn giữa lại chưa được dựng. Ta cần *giả lập* trạng thái đúng như khi đồ thị vừa chạy xong node trước đoạn, rồi cho nó dừng lại ngay sau đoạn.

**Hai cách làm.** 
- Nếu được phép sửa cấu trúc đồ thị, tách đoạn đó thành **subgraph** rồi invoke độc lập là sạch nhất. 

- Nếu không muốn đụng cấu trúc, dùng cơ chế lưu state của LangGraph để dựng điểm dừng (đây sẽ là cách ta sẽ tập trung).




**Các bước thực hiện cho cơ chế lưu State của LangGraph:**

1. **Compile đồ thị với một checkpointer** (`InMemorySaver` là đủ cho test).
2. **Gọi `update_state`** với `as_node` đặt bằng tên node *đứng trước* node ta muốn bắt đầu test — ghi state như thể nó vừa từ node đó chảy ra.
3. **Invoke với `thread_id`** đã dùng ở bước 2, và `interrupt_after` đặt bằng tên node ta muốn dừng lại.

Ví dụ chạy đúng node2 và node3 trong đồ thị bốn node:

```python
# create_graph() dựng đồ thị tuyến tính node1 → node2 → node3 → node4 (mở rộng từ Mục 2)

def test_partial_execution_from_node2_to_node3() -> None:
    checkpointer = MemorySaver()
    graph = create_graph()
    compiled_graph = graph.compile(checkpointer=checkpointer)
    compiled_graph.update_state(
        config={"configurable": {"thread_id": "1"}},                  # thread_id sẽ phải dùng lại y hệt ở invoke
        values={"my_key": "initial_value"},                          # state như lúc kết thúc node1
        as_node="node1",                                            # ghi "như thể đến từ node1" → chạy tiếp sẽ vào node2
    )
    result = compiled_graph.invoke(
        None,                                                       # None = chạy tiếp từ state đã lưu, KHÔNG khởi tạo mới
        config={"configurable": {"thread_id": "1"}},                  # đúng thread_id ở trên mới tìm ra state đó
        interrupt_after="node3",                                    # dừng sau node3 để node4 không chạy
    )
    assert result["my_key"] == "hello from node3"                    # đoạn chạy là node2 → node3, dừng lại
```

**Kết quả** (giá trị được assert):

```
result == {"my_key": "hello from node3"}      ← vào từ node2, dừng sau node3; node1 và node4 không chạy
```

`as_node`, `update_state`, `interrupt_after` là các cơ chế thuộc nhóm persistence/time-travel; ở đây chỉ dùng chúng để dựng điểm dừng cho test.

**!Note:**:
- `as_node` phải là node **đứng trước** node muốn bắt đầu, không phải chính node đó. Muốn bắt đầu ở node2 thì `as_node="node1"`. Đặt nhầm thành `"node2"` thì đoạn chạy lệch đi một node.
- Đầu vào của `invoke` phải là `None` để đồ thị *chạy tiếp* từ state đã lưu. Truyền một dict vào thì nó khởi tạo lại từ đầu, state vừa dựng ở bước 2 bị bỏ. Và `thread_id` ở `invoke` phải trùng `thread_id` ở `update_state`, lệch một ký tự là không tìm thấy state.

## 5. Chọn kỹ thuật nào

| Muốn test gì | Kỹ thuật | Điểm mấu chốt |
|---|---|---|
| Cả luồng đầu-cuối | `invoke(state, config=thread_id)` | Dựng đồ thị + checkpointer mới mỗi test (Mục 2) |
| Đúng một node | `graph.nodes["x"].invoke(state)` | Bỏ qua checkpointer, không cần thread_id (Mục 3) |
| Một đoạn giữa | `update_state(as_node=...)` + `invoke(None, interrupt_after=...)` | Cùng thread_id; đầu vào `None` để chạy tiếp (Mục 4) |
| Một đoạn, được sửa cấu trúc | Tách đoạn thành subgraph, invoke độc lập | Sạch nhất nếu chấp nhận đổi cấu trúc đồ thị |

Chốt lại: cả ba khuôn chỉ khác nhau ở *phạm vi state* cho phép chạy — toàn bộ, một node, hay một lát cắt giữa. Nắm được điểm chung "mỗi test một state sạch" là đủ để không viết ra test đậu-rớt tùy thứ tự.
