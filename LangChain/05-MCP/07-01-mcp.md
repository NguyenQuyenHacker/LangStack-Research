# MCP — dùng tool từ MCP server (`MultiServerMCPClient`)

> MCP (Model Context Protocol) là một giao thức mở chuẩn hóa cách một ứng dụng cung cấp tool và ngữ cảnh cho LLM. Agent LangChain gọi được tool nằm trên MCP server nhờ thư viện `langchain-mcp-adapters`.
> Tool MCP sau khi nạp vào thành tool LangChain bình thường — xem cơ chế tool tại [03-02 Tools](./03-02-tools.md).

---

## 1. Tổng quan

MCP tách phần "định nghĩa tool" ra khỏi agent: tool sống trên một server riêng (tiến trình riêng, thậm chí máy khác), agent chỉ kết nối tới và gọi. `langchain-mcp-adapters` làm cầu nối — nó lấy các tool trên MCP server rồi **chuyển thành tool LangChain**, nên dùng được thẳng trong bất kỳ agent hay workflow LangChain nào.

Khác với tool viết trực tiếp bằng `@tool` (nằm trong cùng tiến trình với agent), tool MCP nằm ngoài tiến trình. Đây là điểm chi phối gần như mọi tính năng còn lại của trang: vì server ở tiến trình khác nên nó không tự thấy được state, store hay context của agent — muốn đưa thông tin đó vào phải qua **interceptor** (mục 7).

```python
from langchain_mcp_adapters.client import MultiServerMCPClient   # client nối tới MCP server
from langchain.agents import create_agent

client = MultiServerMCPClient({...})            # {...} là cấu hình server, xem mục 2
tools = await client.get_tools()                # lấy toàn bộ tool từ các server đã khai báo
agent = create_agent("claude-sonnet-4-6", tools)  # tool MCP dùng như tool thường
```

Tên gọi cần nhớ:

- `MultiServerMCPClient` — client nối tới một hoặc nhiều MCP server cùng lúc.
- `langchain-mcp-adapters` — thư viện cầu nối, cài riêng bằng `pip install langchain-mcp-adapters`.

## 2. Nối nhiều MCP server (`MultiServerMCPClient`)

### Khái niệm

`MultiServerMCPClient` nhận một dict cấu hình, mỗi khóa là một server (đặt tên tùy ý), giá trị mô tả cách kết nối tới server đó. Một client gom nhiều server, `get_tools()` trả về tool gộp từ tất cả.

### Vai trò

Một agent thường cần tool từ nhiều nguồn: một server cho tính toán, một server cho thời tiết, một server nội bộ cho dữ liệu công ty. `MultiServerMCPClient` cho khai báo tất cả trong một chỗ và trộn tool lại thành một danh sách duy nhất đưa cho agent.

### Triển khai

```python
import asyncio
from langchain_mcp_adapters.client import MultiServerMCPClient
from langchain.agents import create_agent

async def main():
    client = MultiServerMCPClient(
        {
            "math": {                              # tên server tự đặt
                "transport": "stdio",              # server chạy như tiến trình con cục bộ
                "command": "python",               # lệnh khởi động tiến trình con
                "args": ["/path/to/math_server.py"],  # đường dẫn tuyệt đối tới file server
            },
            "weather": {
                "transport": "http",               # server từ xa qua HTTP
                "url": "http://localhost:8000/mcp",   # server phải chạy sẵn ở cổng này
            },
        }
    )

    tools = await client.get_tools()               # lấy tool từ cả hai server
    agent = create_agent("claude-sonnet-4-6", tools)

    math_response = await agent.ainvoke(
        {"messages": [{"role": "user", "content": "what's (3 + 5) x 12?"}]}
    )
    weather_response = await agent.ainvoke(
        {"messages": [{"role": "user", "content": "what is the weather in nyc?"}]}
    )
    print(math_response)
    print(weather_response)

if __name__ == "__main__":
    asyncio.run(main())      # get_tools và ainvoke là async, phải chạy trong event loop
```

### Không giữ trạng thái — mặc định

`MultiServerMCPClient` mặc định **stateless**: mỗi lần gọi tool nó mở một `ClientSession` MCP mới, chạy tool, rồi dọn dẹp đóng lại. Không có gì được giữ giữa hai lần gọi. Muốn giữ trạng thái qua nhiều lần gọi thì xem mục 5.

**!Note:** `stdio` có một điểm dễ hiểu nhầm. Bản thân kết nối `stdio` là stateful — tiến trình con sống suốt vòng đời client. Nhưng nếu dùng `MultiServerMCPClient` mà **không** tự quản lý session (mục 5), thì mỗi lần gọi tool vẫn tạo session mới trên tiến trình đó. Server sống dai không đồng nghĩa với session được giữ.

## 3. Tự dựng MCP server (`FastMCP`)

### Khái niệm

`FastMCP` là thư viện để viết MCP server. Khai báo hàm, gắn `@mcp.tool()`, hàm đó thành một tool MCP. Cài bằng `pip install fastmcp`.

### Vai trò

Trang này chủ yếu nói về phía client (nối và gọi). `FastMCP` là phía server, để tự dựng server thử nghiệm hoặc server thật cho tool riêng.

### Triển khai

```python
from fastmcp import FastMCP

mcp = FastMCP("Math")          # tên server

@mcp.tool()                    # biến hàm bên dưới thành tool MCP
def add(a: int, b: int) -> int:
    """Add two numbers"""      # docstring là mô tả tool mà model đọc để quyết định gọi
    return a + b

@mcp.tool()
def multiply(a: int, b: int) -> int:
    """Multiply two numbers"""
    return a * b

if __name__ == "__main__":
    mcp.run(transport="stdio")   # chọn transport: stdio (cục bộ) hoặc http (từ xa)
```

Cơ chế chi tiết của `FastMCP` nằm ở tài liệu FastMCP, không thuộc phạm vi trang này.

## 4. Transports — cách client và server nói chuyện

MCP có nhiều cơ chế truyền (transport). Trang này mô tả `http` và `stdio`, khai báo qua khóa `"transport"` trong cấu hình server.

### 4.1 HTTP (`http` / `streamable-http`)

**Khái niệm.** Transport `http` (còn gọi `streamable-http`) dùng request HTTP để client và server nói chuyện. Server từ xa, nối bằng URL.

**Vai trò.** Dùng khi server chạy độc lập (máy khác, dịch vụ đám mây), agent chỉ có URL.

```python
client = MultiServerMCPClient(
    {
        "weather": {
            "transport": "http",
            "url": "http://localhost:8000/mcp",   # địa chỉ server đã chạy sẵn
        }
    }
)
```

### 4.2 Truyền headers

**Khái niệm.** Thêm header tùy chỉnh (xác thực, tracing…) qua trường `headers` trong cấu hình kết nối.

**Vai trò.** Server HTTP thường đòi token. `headers` là chỗ nhét token cố định vào mọi request tới server đó.

```python
client = MultiServerMCPClient(
    {
        "weather": {
            "transport": "http",
            "url": "http://localhost:8000/mcp",
            "headers": {
                "Authorization": "Bearer YOUR_TOKEN",   # token gắn vào mọi request
                "X-Custom-Header": "custom-value",
            },
        }
    }
)
tools = await client.get_tools()
agent = create_agent("gpt-5.4", tools)
```

**!Note:** `headers` chỉ hỗ trợ cho transport `sse` (MCP đã đánh dấu không còn khuyến nghị) và `streamable_http`. Với `stdio` không có header.

Header cố định như trên là gắn một lần lúc khai báo. Nếu cần đổi header theo từng lời gọi (mỗi tool một token) thì phải dùng interceptor — xem [mục 7.3, "Đổi headers lúc chạy"](#73-viết-interceptor-riêng).

### 4.3 Xác thực (`auth`)

**Khái niệm.** `langchain-mcp-adapters` dùng MCP SDK chính thức bên dưới, cho phép cắm cơ chế xác thực riêng bằng cách hiện thực giao diện `httpx.Auth`, truyền qua trường `auth`.

**Vai trò.** Khi xác thực phức tạp hơn một token tĩnh — ví dụ luồng OAuth cần làm mới token — thì dùng `auth` thay cho `headers`.

```python
client = MultiServerMCPClient(
    {
        "weather": {
            "transport": "http",
            "url": "http://localhost:8000/mcp",
            "auth": auth,        # đối tượng hiện thực httpx.Auth
        }
    }
)
```

Tài liệu trỏ tới hai mẫu tham khảo trong MCP SDK: một mẫu tự viết cơ chế auth, và một luồng OAuth dựng sẵn. Chi tiết hiện thực `httpx.Auth` nằm ngoài phạm vi trang này.

### 4.4 stdio

**Khái niệm.** Client khởi động server như một tiến trình con và nói chuyện qua đầu vào/đầu ra chuẩn (stdin/stdout). Hợp cho tool cục bộ, cấu hình đơn giản.

**Vai trò.** Không cần dựng server HTTP, không cần cổng mạng — chỉ cần một file Python chạy được trên cùng máy.

```python
client = MultiServerMCPClient(
    {
        "math": {
            "transport": "stdio",
            "command": "python",                    # lệnh khởi động tiến trình con
            "args": ["/path/to/math_server.py"],    # đường dẫn tuyệt đối tới file server
        }
    }
)
```

**!Note:** Xem lại ghi chú ở mục 2 — `stdio` giữ tiến trình sống, nhưng session vẫn tạo mới mỗi lần gọi nếu không tự quản lý (mục 5).

## 5. Session giữ trạng thái (`client.session()`)

### Khái niệm

Mặc định mỗi lần gọi tool là một session mới rồi bỏ. `client.session("server_name")` tạo một `ClientSession` bền, giữ nguyên qua nhiều lần gọi, dùng trong khối `async with`.

### Vai trò

Có server phải nhớ ngữ cảnh giữa các lần gọi tool — ví dụ server duy trì một phiên đăng nhập, một con trỏ dữ liệu, hay trạng thái tính toán dở. Session mới mỗi lần sẽ xóa sạch những thứ đó. Session bền giữ lại.

### Áp dụng thực tế

Một MCP server kết nối tới hệ thống nội bộ: lần gọi đầu mở kết nối và xác thực, các lần sau tái dùng kết nối đó để truy vấn. Nếu mỗi lần gọi mở session mới thì mỗi truy vấn phải xác thực lại từ đầu — chậm và có thể vượt giới hạn đăng nhập. Session bền giữ một kết nối cho cả phiên làm việc.

### Triển khai

```python
from langchain_mcp_adapters.client import MultiServerMCPClient
from langchain_mcp_adapters.tools import load_mcp_tools    # nạp tool từ một session cụ thể
from langchain.agents import create_agent

client = MultiServerMCPClient({...})

async with client.session("server_name") as session:       # mở session bền, tự đóng khi ra khỏi khối
    tools = await load_mcp_tools(session)                  # nạp tool gắn với chính session này
    agent = create_agent(
        "google_genai:gemini-3.1-pro-preview",
        tools
    )
```

**!Note:** Ở chế độ mặc định (mục 2) tool nạp bằng `client.get_tools()`. Ở chế độ session bền, tool nạp bằng `load_mcp_tools(session)` để tool gắn với session đó chứ không mở session mới. Dùng nhầm `get_tools()` trong ngữ cảnh này thì mất luôn tính bền — code chạy nhưng không giữ trạng thái.

## 6. Ba loại thứ MCP server cung cấp

MCP server không chỉ có tool. Nó cung cấp ba loại: **tools** (hàm gọi được), **resources** (dữ liệu đọc được), **prompts** (mẫu prompt tái dùng).

### 6.1 Tools

**Khái niệm.** Tool là hàm thực thi mà server phơi ra để LLM gọi — truy vấn database, gọi API, tác động hệ thống ngoài. LangChain chuyển tool MCP thành tool LangChain.

**Vai trò.** Đây là loại cốt lõi. `get_tools()` lấy tool về, phần còn lại (resources, prompts) là bổ trợ.

#### Nạp tool

```python
client = MultiServerMCPClient({...})
tools = await client.get_tools()                  # lấy toàn bộ tool từ các server
agent = create_agent("claude-sonnet-4-6", tools)
```

#### Structured content — dữ liệu máy đọc được kèm theo

**Khái niệm.** Ngoài phần text người đọc được, tool MCP có thể trả kèm **structured content** — dữ liệu máy phân tích được (như JSON). Khi có, adapter bọc nó trong một `MCPToolArtifact` và trả về ở trường `artifact` của `ToolMessage`.

**Vai trò.** Tool vừa cần trả text cho model đọc, vừa cần trả dữ liệu có cấu trúc cho code xử lý (ví dụ một bảng số liệu để vẽ biểu đồ, model không cần đọc từng ô). Hai luồng này tách nhau: text vào hội thoại, structured content vào `artifact`.

**Triển khai — lấy structured content từ artifact.** Sau khi chạy agent, đọc từ các `ToolMessage` trong kết quả:

```python
from langchain.messages import ToolMessage         # lưu ý import path này (xem !Note)

client = MultiServerMCPClient({...})
tools = await client.get_tools()
agent = create_agent("claude-sonnet-4-6", tools)

result = await agent.ainvoke(
    {"messages": [{"role": "user", "content": "Get data from the server"}]}
)

for message in result["messages"]:                 # duyệt mọi message trong kết quả
    if isinstance(message, ToolMessage) and message.artifact:   # chỉ ToolMessage có artifact
        structured_content = message.artifact["structured_content"]   # dữ liệu có cấu trúc
```

**Kết quả in ra** (dựng lại):

```
# structured_content — hình dạng phụ thuộc tool trả gì, ví dụ:
{'orders': [{'id': 1, 'total': 250}, {'id': 2, 'total': 480}], 'count': 2}   ← JSON tool trả kèm, code đọc trực tiếp
```

Ví dụ output trên là suy luận về hình dạng dữ liệu (một dict JSON), không đọc được từ tài liệu — tài liệu chỉ nói `artifact["structured_content"]` chứa structured content. Cần đối chiếu khi chạy thử.

**Triển khai — đẩy structured content vào hội thoại bằng interceptor.** Nếu muốn model **thấy** được structured content trong lịch sử hội thoại (mặc định nó nằm ở `artifact`, model không thấy), dùng interceptor để nối nó vào kết quả tool:

```python
import json
from langchain_mcp_adapters.interceptors import MCPToolCallRequest
from mcp.types import TextContent

async def append_structured_content(request: MCPToolCallRequest, handler):
    """Nối structured content từ artifact vào tool message."""
    result = await handler(request)                # chạy tool bình thường trước
    if result.structuredContent:                   # nếu tool có trả structured content
        result.content += [
            TextContent(type="text", text=json.dumps(result.structuredContent)),  # nối vào dưới dạng text
        ]
    return result

client = MultiServerMCPClient({...}, tool_interceptors=[append_structured_content])
```

Cơ chế interceptor (`tool_interceptors`, `MCPToolCallRequest`, `handler`) giải thích đầy đủ ở mục 7.

**!Note:** Import ở đây là `from langchain.messages import ToolMessage`, còn `MCPToolCallRequest` đến từ `langchain_mcp_adapters.interceptors`. `MCPToolCallRequest` **không phải** là `ToolCallRequest` dùng trong middleware/tools (xem [03-02 Tools](./03-02-tools.md)) — hai kiểu khác nhau, khác cả tên lẫn nơi import. Nhầm hai cái này thì import sai, code không chạy.

#### Nội dung đa phương tiện (multimodal)

**Khái niệm.** Tool MCP có thể trả nội dung nhiều phần (text, ảnh…). Khi server trả nhiều phần, adapter chuyển chúng thành **standard content blocks** của LangChain, đọc qua thuộc tính `content_blocks` trên `ToolMessage`.

**Vai trò.** Xử lý phản hồi đa phương tiện theo một cách thống nhất, không phụ thuộc cách từng MCP server định dạng nội dung của nó.

**Áp dụng thực tế.** Một tool "chụp màn hình trang hiện tại" trả về một mô tả text kèm ảnh base64. `content_blocks` tách sẵn thành khối text và khối image để code xử lý riêng, thay vì phải tự bóc định dạng thô của từng server.

```python
result = await agent.ainvoke(
    {"messages": [{"role": "user", "content": "Take a screenshot of the current page"}]}
)

for message in result["messages"]:
    if message.type == "tool":                     # chỉ xét message loại tool
        print(f"Raw content: {message.content}")   # nội dung thô, định dạng gốc của provider

        for block in message.content_blocks:       # dạng đã chuẩn hóa, tách theo loại
            if block["type"] == "text":
                print(f"Text: {block['text']}")
            elif block["type"] == "image":
                print(f"Image URL: {block.get('url')}")
                print(f"Image base64: {block.get('base64', '')[:50]}...")   # cắt 50 ký tự đầu cho gọn
```

**Kết quả in ra** (dựng lại):

```
Raw content: [...]                                 ← nội dung thô, phụ thuộc provider
Text: Screenshot captured successfully             ← khối text đã tách ra
Image URL: None                                    ← ảnh trả dạng base64 nên không có URL
Image base64: iVBORw0KGgoAAAANSUhEUgAAA...         ← 50 ký tự đầu của chuỗi base64
```

Output trên là dựng lại: hình dạng cụ thể (URL hay base64, nội dung text) tùy tool, tài liệu chỉ mô tả cấu trúc `content_blocks`. Cần đối chiếu khi chạy thử.

### 6.2 Resources

**Khái niệm.** Resource là dữ liệu server phơi ra để client **đọc** — file, bản ghi database, phản hồi API. LangChain chuyển resource MCP thành đối tượng `Blob`, một giao diện chung cho cả nội dung text lẫn nhị phân.

**Vai trò.** Khác tool (gọi để **làm** việc gì), resource là để **đọc** dữ liệu tĩnh. Ví dụ nạp nội dung một file cấu hình, một bản ghi hồ sơ, để đưa vào ngữ cảnh cho agent.

```python
from langchain_mcp_adapters.client import MultiServerMCPClient

client = MultiServerMCPClient({...})

blobs = await client.get_resources("server_name")   # nạp toàn bộ resource của một server

blobs = await client.get_resources(                 # hoặc nạp đúng resource theo URI
    "server_name",
    uris=["file:///path/to/file.txt"]
)

for blob in blobs:
    print(f"URI: {blob.metadata['uri']}, MIME type: {blob.mimetype}")   # nguồn và loại nội dung
    print(blob.as_string())                          # đọc nội dung dạng text
```

**Kết quả in ra** (dựng lại):

```
URI: file:///path/to/file.txt, MIME type: text/plain   ← metadata của blob: nguồn và kiểu MIME
<nội dung file>                                         ← blob.as_string() trả nội dung text
```

Muốn kiểm soát nhiều hơn, dùng `load_mcp_resources` trực tiếp với một session:

```python
from langchain_mcp_adapters.resources import load_mcp_resources

async with client.session("server_name") as session:
    blobs = await load_mcp_resources(session)        # toàn bộ resource qua session
    blobs = await load_mcp_resources(session, uris=["file:///path/to/file.txt"])   # theo URI
```

### 6.3 Prompts

**Khái niệm.** Prompt là mẫu prompt tái dùng mà server phơi ra để client lấy về. LangChain chuyển prompt MCP thành `messages`, ghép thẳng vào workflow dạng chat.

**Vai trò.** Tập trung các mẫu prompt ở server (một chỗ chuẩn), nhiều agent lấy cùng một mẫu về dùng, thay vì mỗi nơi tự viết lại. Prompt nhận tham số để điều chỉnh nội dung.

**Áp dụng thực tế.** Một server giữ mẫu prompt `code_review`. Đội dùng nó cho nhiều dự án, mỗi lần truyền tham số khác nhau (`language`, `focus`) để mẫu tự điều chỉnh — không ai phải chép lại prompt gốc.

```python
from langchain_mcp_adapters.client import MultiServerMCPClient

client = MultiServerMCPClient({...})

messages = await client.get_prompt("server_name", "summarize")   # lấy prompt theo tên

messages = await client.get_prompt(                              # lấy prompt kèm tham số
    "server_name",
    "code_review",
    arguments={"language": "python", "focus": "security"}
)

for message in messages:
    print(f"{message.type}: {message.content}")                  # in loại và nội dung từng message
```

**Kết quả in ra** (dựng lại):

```

human: Review the following python code for security issues.    ← message người dùng, đã điền tham số
```

Output trên dựng lại: nội dung thật do mẫu trên server quyết định, tài liệu không in mẫu. Cần đối chiếu khi chạy thử.

Bản dùng session trực tiếp:

```python
from langchain_mcp_adapters.prompts import load_mcp_prompt

async with client.session("server_name") as session:

        session,
        "code_review",
```

## 7. Interceptor — chèn logic vào lời gọi tool

MCP server chạy ở tiến trình riêng, nên **không** tự truy cập được thông tin runtime của LangGraph: store, context, hay state của agent. **Interceptor bắc cầu chỗ hụt này** — nó cho phép chạm vào ngữ cảnh runtime ngay trong lúc tool MCP thực thi. Ngoài ra interceptor còn cho quyền điều khiển kiểu middleware: sửa request, làm lại khi lỗi (retry), thêm header động, hoặc chặn không cho tool chạy.

Interceptor là hàm `async` nhận vào `request` (kiểu `MCPToolCallRequest`) và `handler`. Truyền vào client qua tham số `tool_interceptors`.

**!Note:** Đây là cơ chế song song với `wrap_tool_call` của middleware trong tool thường (xem [03-02 Tools](./03-02-tools.md) và các file middleware 03-03..03-05), nhưng dành riêng cho tool MCP và dùng kiểu `MCPToolCallRequest` riêng — không dùng chung với `ToolCallRequest` của middleware.

### 7.1 Truy cập runtime context

Khi tool MCP dùng trong agent LangChain (qua `create_agent`), interceptor được truy cập `ToolRuntime` — gồm tool call ID, state, config, và store. Lấy qua `request.runtime`.

Bốn thứ đọc được từ `request.runtime`:

| Đọc từ | Là gì | Dùng để |
|---|---|---|
| `runtime.context` | Cấu hình theo lần gọi (user ID, API key, quyền…) | Nhét thông tin người dùng vào lời gọi tool |
| `runtime.store` | Bộ nhớ dài hạn | Đọc/ghi sở thích, dữ liệu bền qua nhiều hội thoại |
| `runtime.state` | Trạng thái phiên hiện tại | Ra quyết định dựa trên tình huống đang diễn ra |
| `runtime.tool_call_id` | ID của lời gọi tool này | Trả về đúng định dạng, hoặc ghi log theo dõi |

Cơ chế của `ToolRuntime`, `store`, `context`, `state` là kiến thức của các trang khác ([03-02 Tools](./03-02-tools.md), Context engineering, Long-term memory); ở đây chỉ nói interceptor lấy chúng ở đâu.

**Ví dụ — nhét user context vào lời gọi tool** (đọc `runtime.context`):

```python
from dataclasses import dataclass
from langchain_mcp_adapters.interceptors import MCPToolCallRequest

@dataclass
class Context:                                     # khai báo trước những gì context chứa
    user_id: str
    api_key: str

async def inject_user_context(request: MCPToolCallRequest, handler):
    """Nhét thông tin đăng nhập của người dùng vào lời gọi tool MCP."""
    runtime = request.runtime
    user_id = runtime.context.user_id              # lấy user_id truyền vào lúc gọi agent
    api_key = runtime.context.api_key

    modified_request = request.override(           # tạo request mới, thêm user_id vào tham số
        args={**request.args, "user_id": user_id}
    )
    return await handler(modified_request)         # chạy tool với request đã sửa

client = MultiServerMCPClient({...}, tool_interceptors=[inject_user_context])
tools = await client.get_tools()
agent = create_agent("gpt-5.4", tools, context_schema=Context)   # khai báo context_schema để có context

result = await agent.ainvoke(
    {"messages": [{"role": "user", "content": "Search my orders"}]},
    context={"user_id": "user_123", "api_key": "sk-..."}         # context truyền lúc gọi
)
```

**Ví dụ — đọc sở thích từ store** (đọc `runtime.store`):

```python
async def personalize_search(request: MCPToolCallRequest, handler):
    """Cá nhân hóa lời gọi tool bằng sở thích đã lưu trong store."""
    runtime = request.runtime
    user_id = runtime.context.user_id
    store = runtime.store

    prefs = store.get(("preferences",), user_id)   # đọc sở thích của user từ store

    if prefs and request.name == "search":         # chỉ can thiệp tool tên "search"
        modified_args = {
            **request.args,
            "language": prefs.value.get("language", "en"),      # áp ngôn ngữ ưa thích
            "limit": prefs.value.get("result_limit", 10),       # áp số kết quả ưa thích
        }
        request = request.override(args=modified_args)

    return await handler(request)
# client tạo với tool_interceptors=[personalize_search], agent thêm store=InMemoryStore()
```

**Ví dụ — chặn tool nhạy cảm khi chưa xác thực** (đọc `runtime.state`):

```python
from langchain.messages import ToolMessage

async def require_authentication(request: MCPToolCallRequest, handler):
    """Chặn tool MCP nhạy cảm nếu người dùng chưa đăng nhập."""
    runtime = request.runtime
    state = runtime.state
    is_authenticated = state.get("authenticated", False)   # đọc cờ đăng nhập từ state

    sensitive_tools = ["delete_file", "update_settings", "export_data"]

    if request.name in sensitive_tools and not is_authenticated:
        return ToolMessage(                        # trả thẳng lỗi, không gọi handler → tool không chạy
            content="Authentication required. Please log in first.",
            tool_call_id=runtime.tool_call_id,     # phải kèm id để message ghép đúng lời gọi
        )

    return await handler(request)
```

**Ví dụ — giới hạn tần suất, dùng `tool_call_id`** (đọc `runtime.tool_call_id`):

```python
async def rate_limit_interceptor(request: MCPToolCallRequest, handler):
    """Giới hạn tần suất với các tool MCP tốn kém."""
    runtime = request.runtime
    tool_call_id = runtime.tool_call_id

    if is_rate_limited(request.name):              # nếu vượt giới hạn
        return ToolMessage(
            content="Rate limit exceeded. Please try again later.",
            tool_call_id=tool_call_id,
        )

    result = await handler(request)
    log_tool_execution(tool_call_id, request.name, success=True)   # ghi log lời gọi thành công
    return result
```

**Kết quả in ra** (dựng lại) — khi interceptor `require_authentication` chặn một tool nhạy cảm lúc state chưa xác thực:

```
# model gọi tool "delete_file", state.authenticated = False
ToolMessage(content="Authentication required. Please log in first.", ...)   ← tool không chạy, model nhận lại thông báo này
```

Cơ chế trả `ToolMessage` để chặn (không gọi `handler`) và trả `Command` để điều khiển luồng nói ở mục 7.2 và 7.3.

### 7.2 Cập nhật state và điều khiển luồng (`Command`)

**Khái niệm.** Interceptor trả về đối tượng `Command` để cập nhật state của agent hoặc điều khiển luồng chạy của graph — đánh dấu tiến độ, chuyển sang agent khác, hoặc kết thúc sớm.

**Vai trò.** Không chỉ sửa request/response, interceptor còn tác động vào luồng tổng của agent. Ví dụ khi tool "gửi đơn" chạy xong, đánh dấu nhiệm vụ hoàn thành và chuyển sang agent tổng kết.

`Command` (`update=`, `goto=`) là khái niệm của LangGraph, cơ chế đầy đủ nằm ở trang multi-agent; ở đây chỉ nói interceptor trả nó ra được.

```python
from langgraph.types import Command

async def handle_task_completion(request: MCPToolCallRequest, handler):
    """Đánh dấu xong việc rồi bàn giao cho agent tổng kết."""
    result = await handler(request)

    if request.name == "submit_order":             # sau khi tool submit_order chạy xong
        return Command(
            update={                               # cập nhật state
                "messages": [result] if isinstance(result, ToolMessage) else [],
                "task_status": "completed",
            },
            goto="summary_agent",                  # chuyển luồng sang agent tên summary_agent
        )

    return result
```

Kết thúc sớm bằng `goto="__end__"`:

```python
async def end_on_success(request: MCPToolCallRequest, handler):
    """Kết thúc lần chạy khi nhiệm vụ được đánh dấu xong."""
    result = await handler(request)

    if request.name == "mark_complete":
        return Command(
            update={"messages": [result], "status": "done"},
            goto="__end__",                        # "__end__" là chặng kết thúc, dừng agent
        )

    return result
```

### 7.3 Viết interceptor riêng

Interceptor là hàm `async` bọc quanh việc chạy tool: cho sửa request trước, sửa response sau, hoặc bỏ qua hẳn việc chạy tool. Chúng xếp theo kiểu **"củ hành"** — cái đầu tiên trong danh sách là lớp ngoài cùng.

**Mẫu cơ bản.** Nhận `request` và `handler`. Sửa request trước khi gọi `handler`, sửa kết quả sau, hoặc không gọi `handler`:

```python
from langchain_mcp_adapters.interceptors import MCPToolCallRequest

async def logging_interceptor(request: MCPToolCallRequest, handler):
    """Ghi log lời gọi tool trước và sau khi chạy."""
    print(f"Calling tool: {request.name} with args: {request.args}")   # trước khi chạy
    result = await handler(request)                                    # chạy tool
    print(f"Tool {request.name} returned: {result}")                   # sau khi chạy
    return result

client = MultiServerMCPClient(
    {"math": {"transport": "stdio", "command": "python", "args": ["/path/to/server.py"]}},
    tool_interceptors=[logging_interceptor],
)
```

**Kết quả in ra** (dựng lại) — khi model gọi tool `add(a=2, b=3)`:

```
Calling tool: add with args: {'a': 2, 'b': 3}     ← in trước, args là tham số model gửi
Tool add returned: 5                               ← in sau, result là kết quả tool trả
```

**Sửa request — `request.override()`.** Tạo request mới đã sửa, request gốc giữ nguyên (bất biến):

```python
async def double_args_interceptor(request: MCPToolCallRequest, handler):
    """Nhân đôi mọi tham số số trước khi chạy."""
    modified_args = {k: v * 2 for k, v in request.args.items()}   # nhân đôi từng tham số
    modified_request = request.override(args=modified_args)       # tạo request mới, không sửa bản gốc
    return await handler(modified_request)

# Lời gọi gốc add(a=2, b=3) thành add(a=4, b=6)
```

**Đổi headers lúc chạy.** Interceptor đổi header HTTP động theo ngữ cảnh request — mỗi tool một token:

```python
async def auth_header_interceptor(request: MCPToolCallRequest, handler):
    """Thêm header xác thực theo tool đang được gọi."""
    token = get_token_for_tool(request.name)                      # token khác nhau theo tool
    modified_request = request.override(
        headers={"Authorization": f"Bearer {token}"}
    )
    return await handler(modified_request)
```

Đây là phần bù cho giới hạn của `headers` tĩnh ở [mục 4.2](#42-truyền-headers): header tĩnh gắn một lần lúc khai báo, còn cách này đổi theo từng lời gọi.

**Ghép nhiều interceptor — thứ tự "củ hành".** Cái đầu danh sách là lớp ngoài cùng:

```python
async def outer_interceptor(request, handler):
    print("outer: before")
    result = await handler(request)
    print("outer: after")
    return result

async def inner_interceptor(request, handler):
    print("inner: before")
    result = await handler(request)
    print("inner: after")
    return result

client = MultiServerMCPClient({...}, tool_interceptors=[outer_interceptor, inner_interceptor])
```

**Kết quả in ra** (chép từ tài liệu — đây là output tài liệu có nêu):

```
outer: before      ← lớp ngoài chạy phần "before" trước
inner: before      ← rồi tới lớp trong
                   (tool thực thi ở giữa)
inner: after       ← lớp trong chạy "after" trước
outer: after       ← lớp ngoài "after" sau cùng
```

**Xử lý lỗi — retry.** Bắt lỗi khi chạy tool và làm lại với thời gian chờ tăng dần:

```python
import asyncio

async def retry_interceptor(request: MCPToolCallRequest, handler, max_retries: int = 3, delay: float = 1.0):
    """Làm lại lời gọi lỗi với thời gian chờ tăng gấp đôi mỗi lần."""
    last_error = None
    for attempt in range(max_retries):
        try:
            return await handler(request)          # thử chạy tool
        except Exception as e:
            last_error = e
            if attempt < max_retries - 1:
                wait_time = delay * (2 ** attempt)  # 1s, 2s, 4s... (tăng gấp đôi)
                print(f"Tool {request.name} failed (attempt {attempt + 1}), retrying in {wait_time}s...")
                await asyncio.sleep(wait_time)
    raise last_error                               # hết lượt vẫn lỗi thì ném lỗi cuối
```

**Xử lý lỗi — phương án dự phòng.** Bắt đúng loại lỗi và trả giá trị thay thế:

```python
async def fallback_interceptor(request: MCPToolCallRequest, handler):
    """Trả giá trị dự phòng nếu tool chạy lỗi."""
    try:
        return await handler(request)
    except TimeoutError:                           # quá thời gian chờ
        return f"Tool {request.name} timed out. Please try again later."
    except ConnectionError:                        # không nối được tới server
        return f"Could not connect to {request.name} service. Using cached data."
```

**!Note:** `request.override()` trả về request **mới**, không sửa request cũ. Viết `request.override(args=...)` mà không gán lại và không truyền bản mới vào `handler` thì thay đổi bị bỏ — code chạy, tool vẫn nhận tham số cũ, không báo lỗi.

## 8. Progress notifications — theo dõi tiến độ tool chạy lâu

**Khái niệm.** Đăng ký nhận cập nhật tiến độ cho tool chạy lâu, qua callback `on_progress` truyền vào lớp `Callbacks`.

**Vai trò.** Tool chạy lâu (xử lý lô lớn, tải file nặng) mà không có phản hồi thì người dùng nhìn màn hình đứng im. Callback tiến độ cho phép in phần trăm hoàn thành theo thời gian thực.

**Áp dụng thực tế.** Một tool MCP xử lý 10.000 bản ghi, chạy 90 giây. Server phát tiến độ dần; callback in "Progress: 45.0%" để người dùng biết tool vẫn đang chạy chứ không treo.

```python
from langchain_mcp_adapters.callbacks import Callbacks, CallbackContext

async def on_progress(progress: float, total: float | None, message: str | None, context: CallbackContext):
    """Nhận cập nhật tiến độ từ MCP server."""
    percent = (progress / total * 100) if total else progress   # có total thì tính %, không thì lấy số thô
    tool_info = f" ({context.tool_name})" if context.tool_name else ""
    print(f"[{context.server_name}{tool_info}] Progress: {percent:.1f}% - {message}")

client = MultiServerMCPClient({...}, callbacks=Callbacks(on_progress=on_progress))
```

**Kết quả in ra** (dựng lại):

```
[weather (fetch_forecast)] Progress: 25.0% - Downloading data     ← server, tool, %, và message kèm theo
[weather (fetch_forecast)] Progress: 50.0% - Processing
[weather (fetch_forecast)] Progress: 100.0% - Done
```

`CallbackContext` cung cấp `server_name` (tên server) và `tool_name` (tên tool đang chạy, có trong lúc gọi tool).

## 9. Logging — nhận log từ server

**Khái niệm.** Giao thức MCP hỗ trợ server gửi thông báo log. Dùng lớp `Callbacks` với `on_logging_message` để đăng ký nhận.

**Vai trò.** Xem log của server ngay tại phía client — tiện gỡ lỗi khi tool cư xử lạ mà không phải mở riêng log của server.

```python
from langchain_mcp_adapters.callbacks import Callbacks, CallbackContext
from mcp.types import LoggingMessageNotificationParams

async def on_logging_message(params: LoggingMessageNotificationParams, context: CallbackContext):
    """Nhận log từ MCP server."""
    print(f"[{context.server_name}] {params.level}: {params.data}")   # tên server, mức log, nội dung

client = MultiServerMCPClient({...}, callbacks=Callbacks(on_logging_message=on_logging_message))
```

**Kết quả in ra** (dựng lại):

```
[math] info: Received request to add 2 and 3       ← server, mức log (info), nội dung server gửi
[math] error: Division by zero attempted           ← mức error khi server gặp lỗi
```

## 10. Elicitation — server xin thêm input từ người dùng

### Khái niệm

Elicitation cho phép MCP server hỏi thêm input từ người dùng **trong lúc** tool chạy. Thay vì đòi mọi input ngay từ đầu, server hỏi tương tác khi cần.

### Vai trò

Có tool không biết trước mình cần gì cho tới lúc chạy. Ví dụ tool tạo hồ sơ: chạy đến đâu phát hiện thiếu email, tuổi thì hỏi ngay lúc đó. Elicitation là cơ chế server dừng lại giữa chừng xin dữ liệu rồi chạy tiếp.

### Áp dụng thực tế

Tool `create_profile` nhận tên, nhưng cần thêm email và tuổi. Thay vì báo lỗi "thiếu tham số" bắt gọi lại từ đầu, tool dùng `ctx.elicit()` hỏi ngay, người dùng cấp, tool hoàn tất trong một lần chạy.

### Phía server — dùng `ctx.elicit()`

```python
from pydantic import BaseModel
from mcp.server.fastmcp import Context, FastMCP

server = FastMCP("Profile")

class UserDetails(BaseModel):                       # khai báo schema dữ liệu cần xin
    email: str
    age: int

@server.tool()
async def create_profile(name: str, ctx: Context) -> str:
    """Tạo hồ sơ người dùng, xin thêm chi tiết qua elicitation."""
    result = await ctx.elicit(                      # dừng lại xin input theo schema
        message=f"Please provide details for {name}'s profile:",
        schema=UserDetails,
    )
    if result.action == "accept" and result.data:   # người dùng cấp dữ liệu hợp lệ
        return f"Created profile for {name}: email={result.data.email}, age={result.data.age}"
    if result.action == "decline":                   # người dùng từ chối cung cấp
        return f"User declined. Created minimal profile for {name}."
    return "Profile creation cancelled."             # người dùng hủy hẳn

if __name__ == "__main__":
    server.run(transport="http")
```

### Phía client — xử lý bằng callback

Client cung cấp callback `on_elicitation` cho `MultiServerMCPClient` để trả lời yêu cầu xin input:

```python
from langchain_mcp_adapters.callbacks import Callbacks, CallbackContext
from mcp.shared.context import RequestContext
from mcp.types import ElicitRequestParams, ElicitResult

async def on_elicitation(mcp_context: RequestContext, params: ElicitRequestParams, context: CallbackContext) -> ElicitResult:
    """Xử lý yêu cầu elicitation từ MCP server."""
    # Ứng dụng thật sẽ hỏi người dùng dựa trên params.message và params.requestedSchema
    return ElicitResult(
        action="accept",                            # trả về hành động và dữ liệu
        content={"email": "user@example.com", "age": 25},
    )

client = MultiServerMCPClient(
    {"profile": {"url": "http://localhost:8000/mcp", "transport": "http"}},
    callbacks=Callbacks(on_elicitation=on_elicitation),
)
```

### Ba hành động callback trả về

| Hành động | Nghĩa |
|---|---|
| `accept` | Người dùng cấp input hợp lệ. Dữ liệu để trong trường `content`. |
| `decline` | Người dùng chọn không cung cấp thông tin được hỏi. |
| `cancel` | Người dùng hủy hẳn thao tác. |

```python
ElicitResult(action="accept", content={"email": "user@example.com", "age": 25})   # cấp kèm dữ liệu
ElicitResult(action="decline")                                                    # từ chối cung cấp
ElicitResult(action="cancel")                                                     # hủy thao tác
```
